# jellyfish finger

> 又名 Jelly Dream。初始页是钩织(crochet)白线风。

用手势指挥一群水母。摄像头识别你的手,食指指尖走到哪里,水母就游向哪里。

浏览器直接跑,不需要任何额外硬件。**摄像头画面只在本机处理,不会上传、不会保存。**

👉 网页版:`https://<你的用户名>.github.io/jelly-dream/`
👉 桌面版:见 [Releases](../../releases)

---

## 玩法

| 动作 | 反应 |
|---|---|
| 移动食指 | 水母跟着游过来,各自绕着指尖公转 |
| 靠近水母 | 伞盖发亮,触须散开,响起一声轻铃 |
| 快速划动 | 掀起水波,推开水母,冒出气泡 |
| 捏住拇指和食指 | 水母收拢到指尖,缩成一颗颗发光水滴 |
| 再张开手指 | 放出一只新的小水母(最多 12 只) |
| 摊开手掌停住 | 水母均分成一圈,绕着掌心缓慢旋转 |
| 手离开画面 | 一秒多以后水母恢复自由巡游 |
| 两只手一起举起 | 各自带一群水母,中间拉出一道流动的水流 |
| 两只手交叉换位 | 水母跟着各自那只手走,不会互相跳过去 |
| 右下角快门 / 按 `R` | 录 10 秒(含声音),可存视频、存 GIF 或直接分享 |

> GIF 取的是前 5 秒、12fps、440px 宽,大约 1–2MB;视频是完整 10 秒的原分辨率。

右上角开关:摄像头背景 · 美颜 · 水母样式(手绘 / 原图贴图) · 水波折射 · 波点 · 声音。

## 技术构成

```
摄像头 → MediaPipe Hands(21 个关键点) → 食指指尖坐标 → Canvas 2D 渲染 + Web Audio 合成
```

- **手部识别** [@mediapipe/hands](https://www.npmjs.com/package/@mediapipe/hands),最多两只手,识别跑 30fps,渲染跑 60fps,互不阻塞。
  两只手分槽位时先认 MediaPipe 给的左右手标签,认不出来再按指尖距离就近分配 —— 光靠就近分配,两手交叉的瞬间会互换,
  跟着这只手的那群水母就会整体瞬移到另一只手上
- **背景** 摄像头画面降到 420px 缓冲后按横切片做正弦位移(水下折射),再叠淡彩水洗
- **美颜** 1/4 降采样柔化层回贴(磨皮)+ screen 混合柔光 + 少量血色
- **水母** 两套渲染:代码绘制(触手是链式物理,会甩会被水流推)/ 原图贴图(切片位移驱动摆动)
- **声音** 全部 Web Audio 现场合成,不加载任何音频文件。不是「随机取五声音阶」,而是一个会缓慢平移的和声场:
  `Dm9 → Cadd9/6 → B♭maj9 → Am11`,四个九和弦保持排列一起往下平移、不做功能性解决 —— 也就是 planing(平行和弦)。
  所有发声事件只从当前和弦取音,所以随便乱按也不会撞到不协和;旋律是从和弦里浮出来的,不是写死的
- **音色** 铃是钢片琴(第四泛音故意偏 4%,金属感就来自这点不谐),快速划动是竖琴滑奏,捏合是一块平行和弦整体下移。
  两成概率往上挂一个不解决的倚音。混响脉冲带 25ms 预延迟,整条链路末端一个 2.2kHz 低通统一削齿音。
  想调就改 `Snd.TONE` 的 `vol` / `bright` / `room`;嫌音偏高的话低通没用,改 `bell()` 里的 `deg(i, 1)` 为 `deg(i, 0)` 整体降八度
- **录制** canvas.captureStream + MediaRecorder(自带音轨);GIF 是自己写的 GIF89a 编码器(中位切分取色板 + 有序抖动 + LZW),分帧编码不卡界面。
  取 128 色而不是 256:实测体积小两成,平均色差只差 0.08/255

零运行时依赖,全部原生 API。

## 本地开发

```bash
npm install          # 会自动把 MediaPipe 模型复制到 app/vendor
npm run serve        # → http://localhost:5173
```

> ⚠️ 别用 `file://` 直接双击 `app/index.html` 打开,浏览器不会给摄像头权限。必须走 `localhost` 或 `https`。

跑桌面版:

```bash
npm start
```

## 打包

```bash
npm run dist:mac     # → release/*.dmg
npm run dist:win     # → release/*.exe
```

**跨平台打不了**:mac 的 dmg 只能在 macOS 上构建,Windows 的 exe 建议在 Windows 上构建。所以直接用 CI:

```bash
git tag v0.1.0
git push origin v0.1.0
```

`.github/workflows/release.yml` 会同时在 macOS 和 Windows 机器上构建,产物自动挂到 Release。

## 关于签名

现在打出来的包**没有签名**,用户首次打开会看到警告:

- **macOS 14 及以前**:右键点图标 → 打开 → 再点「打开」
- **macOS 15 (Sequoia) 起**:右键打开这条路 Apple 已经关掉了。先双击一次(会被拦),再去「系统设置 → 隐私与安全性」,往下拉会出现「仍要打开」
- 两者都可以用终端一步解决:`xattr -dr com.apple.quarantine "/Applications/Jelly Dream.app"`
- 如果报的是「已损坏,无法打开」而不是「无法验证开发者」,那是 Apple Silicon 上缺签名,不是文件坏了:`codesign --force --deep --sign - "/Applications/Jelly Dream.app"`
- **Windows**:SmartScreen 蓝屏 → 点"更多信息" → "仍要运行"

要去掉警告需要付费证书:

| | 费用 | 说明 |
|---|---|---|
| Apple Developer Program | $99 / 年 | 之后还要做 notarization(公证) |
| Windows 代码签名证书 | 约 $200–400 / 年 | OV 证书仍会攒信誉期,EV 证书立即生效 |

个人项目初期完全可以不签名,在 README 里写清楚打开方式就行。要签的时候,把证书放进 GitHub Secrets,在 workflow 里配 `CSC_LINK` / `CSC_KEY_PASSWORD`(mac)和 `WIN_CSC_LINK`(win)即可。
